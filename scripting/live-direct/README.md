# Live Direct · Scripting 独立版

把整个 Live Direct 后端搬进 iPhone / iPad 上的 [Scripting](https://apps.apple.com/app/scripting/id6479691128) App：不需要 NAS 或服务器，手机直接请求抖音、B站、斗鱼、虎牙的公开接口解析直播地址。

## 功能

- **完整后台**：总览（本机服务开关、订阅地址、各平台状态与频道数、警告）、平台页（启用开关、手动房间、抖音分享链接、分类/分区热门、数量与人气门槛、画质、B站 H.264 偏好）、B站扫码登录 / 手动填写 SESSDATA、频道预览。
- **本机订阅服务**：脚本在手机上运行一个 HTTP 服务，路由与 NAS 版完全相同：
  - `http://127.0.0.1:19070/s/令牌/interface.m3u`：M3U 订阅，APTV 等播放器直接添加；
  - `/s/令牌/live/平台/房间`：每次播放时现场解析，302 跳转到平台 CDN；
  - `/s/令牌/hls/平台/房间`：只取 HLS（斗鱼没有 HLS，返回 404）。
  - 可选“允许局域网访问”，同一 Wi-Fi 下的 Apple TV 等设备用 `http://手机IP:19070/…` 订阅。
- **频道列表与关注**：搜索、按平台筛选；左滑或长按关注，关注的主播置顶，下播后保留（灰色）。
- **播放**：外部播放器（APTV / VLC / Infuse / 自定义 URL Scheme），或 Scripting 内置播放器（系统 AVPlayer，支持画中画；带 Referer 请求头播放 HLS）。

## 安装

1. 在 Scripting 里新建一个名为 `Live Direct` 的脚本，把本目录的所有文件按原样放进去，包括 `core/` 子目录：
   `script.json`、`index.tsx`、`backend.ts`、`store.ts`、`transport.ts`、`messages.ts`、`player.tsx`、`overview-page.tsx`、`platform-page.tsx`、`channels-page.tsx`、`settings-page.tsx`，以及 `core/` 下的 9 个 `.ts` 文件。
2. 运行脚本，本机服务会自动启动。到“总览 → 平台”里启用平台、添加主播或分类，下拉刷新。
3. 在“总览”点“复制订阅并打开 APTV”，在 APTV 里添加这个订阅。

## 运行方式（重要）

播放器每次播放都要向本机服务取地址，所以**看直播期间 Scripting 需要保持运行**：

- 下滑关闭页面：脚本最小化到后台，服务继续运行；在 Scripting 的运行中脚本列表里可以重新打开。
- 点“退出”：停止服务并结束脚本，APTV 里的频道随即无法播放。
- “后台保活”（默认开启）会在切到后台时申请继续运行，耗电会增加；iOS 仍可能在内存紧张时结束后台进程。这时回到 Scripting 重新运行脚本即可。

## 播放限制

| 平台 | 外部播放器（APTV 等） | Scripting 内置播放器 |
| --- | --- | --- |
| 抖音 | ✅ 优先 FLV | 取 HLS |
| B站 | ✅ | 取 HLS（ts / fmp4） |
| 虎牙 | ✅ | 取 HLS |
| 斗鱼 | ✅ | ❌ 只有 FLV，系统播放器不支持 |

- 302 跳转不能携带 Referer 等请求头。B站部分 CDN 节点不带 Referer 会返回 403，部分节点在某些网络下 TLS 失败，所以 B站解析时会先用不带请求头的 HEAD 探测最多 4 个候选节点，选第一个能访问的（NAS 版相同）；其他平台的 CDN 实测不需要请求头。内置播放器会带上 Referer。
- APTV 没有公开的“播放指定地址”链接格式；选 APTV 时会复制该频道的播放地址并用 `aptv://` 打开 APTV，在本机订阅里点同名频道即可。
- 分类来自平台公开页面，不是账号的关注或推荐。B站登录只用于获取账号本来有权限的画质，不绕过会员/付费限制。

## 隐私与安全

- 订阅令牌和 SESSDATA 只存本机钥匙串；配置存 Scripting 的脚本私有存储，不含 SESSDATA。
- 只请求固定的官方接口域名，只把 302 跳转到校验过的官方 CDN 域名；不执行网页脚本、不代理视频流。
- 未开启局域网访问时，只接受来自本机（127.0.0.1 / ::1）的请求，其他设备一律 403。Scripting 3.3.0 实测忽略 `listenAddressIPv4`，服务实际仍监听所有网卡，所以改为按请求来源地址拒绝。开启局域网访问后接受同一网络的设备。无论哪种情况，订阅地址里的随机令牌都是访问凭据，不要分享，设置里可以重置。

## 实现与验证

- `core/` 是 Python 服务端 `live_direct/` 的 TypeScript 移植（平台解析与签名、配置校验、发现与缓存引擎），不依赖 Scripting，可在 Node 中测试。
- `scripting/tests/gen_cases.py` 用 Python 版生成对照用例，`scripting/tests/run.mjs` 检查 TS 移植的输出完全一致（546 个用例）；`scripting/tests/backend.test.mjs` 用 Scripting API 的替身测试本机服务的令牌校验、来源地址限制、M3U 与 302/404 行为。CI 会运行这些检查。
- 全部 `.ts` / `.tsx` 已用 Scripting App 同步的 `.d.ts`（`scripting-cli` 1.5.0）做过 `tsc --strict` 类型检查，没有错误。

### 真机验证（2026-10-22，iPhone，iOS 27.2，Scripting 3.3.0 (32)，中国大陆网络）

已验证：

- 脚本启动后总览显示“运行中 · 端口 19070”；Safari 打开本机订阅地址能拿到 M3U。
- 本机服务：频道未就绪时返回 503，刷新后返回 200 的 M3U（GET / HEAD）；四个平台的 `/live/` 都 302 到官方 CDN；`/hls/` 抖音、B站、虎牙 302，斗鱼 404；错误令牌、未知房间、未知路径 404，POST 405。
- 局域网：关闭时同一 Wi-Fi 的另一台电脑访问得到 403，本机 200；开启后另一台电脑可以访问（只测了能否连上，没在 Apple TV 上播放）。
- 抖音：分享链接（v.douyin.com）、网页房间号、分类热门。
- B站：手动房间、分区热门；扫码登录，通过“在 B站 App 中打开”在同一台手机上确认成功；手动填写无效 SESSDATA 时显示中文错误。
- 斗鱼：手动房间、分类热门。
- 虎牙：手动房间、分类热门；连续三次解析同一房间分别换到了不同线路。
- APTV：添加本机订阅后四个平台都能播放；最小化脚本（开启后台保活）后，APTV 连续 10 分钟以上换台都正常。
- 内置播放器：抖音、B站、虎牙的 HLS 都能播放；斗鱼的点击菜单和长按菜单里都没有内置播放。
- 关注、取消关注、上移/下移；关注的主播不在当前列表时显示为灰色（通过关闭该平台模拟，没等到真实下播）；退出后重新运行，配置和关注列表都还在。
- 失败路径：无效房间号显示中文提示；飞行模式下刷新，平台显示红色“刷新失败”，频道页保留上次成功的列表。

未验证或结论不完整：

- 点“退出”后服务是否立即停止：反馈已退出后几秒内局域网请求仍有响应，约两分钟后才连不上；期间同步连接断开又重连过，可能有调试会话重新运行的另一个实例，原因没有查清。
- 后台保活能维持的上限，以及 iOS 在内存紧张时结束进程后的表现（只测到 10 分钟以上）。
- Apple TV 等局域网设备上的实际播放。
- 手动填写有效的 SESSDATA（有效值的保存只经扫码登录路径验证过）。
- 频道列表里“外部播放器打开”跳转 APTV / VLC / Infuse / 自定义 URL Scheme。
- iPad 上的侧边栏布局。
